# Auth Manifest (`auth.juvantia.org`)

**Service**: `auth`
**Domain**: `https://auth.juvantia.org`
**Core Tech**: Next.js (App Router), SuperTokens, ZeroDev (Smart Wallets), PostgreSQL.

---

## 🏗️ Описание
Централизованный сервис единого входа (SSO) и управления профилями пользователей во всей экосистеме Juvantia. Сервис отвечает не только за авторизацию, но и за генерацию обязательных смарт-кошельков (Smart Accounts) для каждого игрока.

---

## ⚙️ Технологии и Интеграции

### 1. SuperTokens (SSO)
*   **Метод**: Passwordless (OTP по Email).
*   **Сессии**: Используются кросс-доменные куки (`.juvantia.org`), что позволяет пользователю один раз войти на `auth.juvantia.org` и быть авторизованным на всех поддоменах (`city`, `fabrica`, `deck`, `forum`).
*   **JWT**: Сервис генерирует кастомные JWT, которые содержат `email`, `name`, и `avatar_url` для быстрого доступа других микросервисов.

### 2. ZeroDev (Smart Accounts)
*   **Тип**: Account Abstraction (ERC-4337) в сети **Base L2**.
*   **Ключи**: Passkeys (WebAuthn). Пользователю не нужно хранить сид-фразу; доступ к кошельку осуществляется через биометрию устройства (FaceID/TouchID).
*   **Onboarding**: Каждый пользователь обязан создать кошелек при первом входе.

### 3. PostgreSQL (Shared DB)
*   Сервис использует общую базу данных экосистемы — `juvantia`.
*   Таблица `users` является ЕДИНОЙ точкой правды для всех сервисов.

---

## 📊 Структура данных (Table: `users`)

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `supertokens_id` | `VARCHAR(255)` | **PK**. Уникальный ID из SuperTokens. |
| `email` | `VARCHAR(255)` | Email пользователя (синхронизируется из SSO). |
| `name` | `VARCHAR(255)` | Полное имя пользователя (обязательно). |
| `username` | `VARCHAR(255)` | Уникальный никнейм (без @). |
| `avatar_url` | `TEXT` | Ссылка на аватар или DataURL. |
| `smart_wallet_address`| `VARCHAR(255)` | Публичный адрес кошелька на Base L2. |
| `passkeys` | `JSONB` | Массив публичных ключей привязанных устройств. |

---

## 🔄 Логика работы (Auth Flow)

1.  **Вход**: Пользователь вводит Email -> Получает код -> Входит.
2.  **Проверка профиля (`GET /api/user/profile`)**:
    *   Если в БД нет записи или отсутствуют обязательные поля (`name`, `username`, `smart_wallet_address`) -> возвращается `needsOnboarding: true`.
3.  **Онбординг (`POST /api/user/profile`)**:
    *   Пользователь выбирает ник, имя и создает Passkey (через интерфейс ZeroDev).
    *   Фронтенд отправляет данные на бэкенд, который делает **UPSERT** в таблицу `users`.
4.  **Dashboard**: После онбординга пользователь видит данные своего профиля и смарт-кошелька.

## 🚀 Деплой и Окружение
*   **Автоматизация**: GitHub Actions (`deploy.yml`) -> SSH -> `git pull` -> `docker build` на VPS.
*   **Контейнеры**: `auth-service` (Next.js) и `supertokens` (Core).
*   **Файл конфигурации**: `.env.local` (генерируется из GitHub Secret `ENV_LOCAL`).
*   **Важные переменные**:
    *   `POSTGRES_URI`: Строка подключения к базе.
    *   `NEXT_PUBLIC_ZERODEV_PROJECT_ID`: ID проекта.

---

**Важное замечание для ИИ**: 
При работе с базой данных `users` всегда делайте **UPSERT** по `supertokens_id`. Если вы добавляете функционал в другие сервисы (`fabrica`, `deck`), берите данные пользователя именно из этой таблицы, чтобы обеспечить консистентность профилей.
